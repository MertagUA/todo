# Завдання — локальний планувальник

**Живий застосунок: https://mertagua.github.io/todo/**

Бічна панель із проєктами (Життя, Робота, Весілля, Навчання — які створиш сам),
календар із подіями по годинах і планер тижня з перетягуванням завдань.
Усе зберігається у `localStorage` браузера: без сервера, без акаунтів, без інтернету.

Зроблено на **Vue 3** (`<script setup>`) + **Vite**.

## Запуск

```bash
npm install
npm run dev
```

Відкриється http://localhost:5173.

## Іконка застосунку в Dock

```bash
npm run app
```

Створює **`~/Applications/Завдання.app`**. Знайди через Spotlight («Завдання»)
або у Finder → Програми, і перетягни в Dock.

Один клік по іконці:
1. перезбирає застосунок, якщо ти щось міняв у `src/`,
2. піднімає локальний сервер на порту 5173, якщо він ще не працює,
3. відкриває вікно Chrome без вкладок і адресного рядка (якщо Chrome немає — типовий браузер).

Порт той самий, що й у `npm run dev`, тож дані спільні.

**Нічого не працює у фоні саме по собі.** Немає автозапуску й служб. Поки вікно
відкрите, сторінка кожні 20 с пінгує сервер; закриєш вікно — сервер сам вимкнеться
десь за 3 хвилини (до того ~40 МБ памʼяті). `npm run stop` вимикає одразу.

- Лог: `~/Library/Logs/Tasks.log`
- Інша назва: `APP_NAME="Плани" npm run app`
- Інший порт: `PORT=5180 npm run app` (увага: інший порт = порожнє сховище, спершу зроби експорт)
- Перенесеш теку проєкту — запусти `npm run app` ще раз (шлях зашитий у launcher)

## Розділи

### Завдання
- Обовʼязкова лише **назва**. Решта — за бажанням: опис, дедлайн, пріоритет, теги, проєкт.
- Клік по завданню відкриває панель праворуч; кожна зміна зберігається одразу.
- Розумні добірки: Усі, Сьогодні, Найближчі, Прострочені, Повторювані, Виконані.
- Панель інструментів: пошук, сортування, «Сховати виконані», прогрес, «Прибрати виконані».

### Повторювані завдання
Полити квіти щодня, день народження щороку, спортзал у Пн/Ср/Пт.
Позначаєш виконаним — завдання **не закривається**, а переїжджає на наступну дату,
знизу зʼявляється підказка з кнопкою «Повернути». Пропущені дні не накопичуються:
забув на тиждень — завдання все одно повернеться один раз, завтра.

### Дні роботи (окремо від дедлайну)
Дедлайн 25-го, а робити плануєш 21, 23 і 24 — саме для цього поле **«Дні роботи»**
у панелі завдання. Ці дні:
- підтягуються у добірку **Сьогодні** (разом із тим, що має дедлайн сьогодні),
- показуються у **календарі** у смузі «увесь день»,
- складають колонки **планера тижня**.

### Календар
- Режими **Місяць**, **Тиждень** і **День**.
- Місяць: шість тижнів Пн–Нд, у клітинці події (час + назва) і заплановані завдання,
  `+N ще` відкриває цей день. Клік по числу — теж перехід у режим дня, клік по клітинці
  створює подію.
- Тиждень і день: сітка по годинах 00:00–23:00, червона лінія поточного часу.
- Клік по порожньому місцю створює подію на цей час (крок 15 хв).
- Подія має початок і **необовʼязкову тривалість**: мітинг о 15:00 на 1,5 год займає
  блок з 15:00 до 16:30. Якщо тривалість невідома — блок малий, з пунктиром і «?».
- Тривалість: сім швидких кнопок, випадний список від 5 хв до 12 год і поле для
  будь-якого свого числа хвилин (наприклад 37). Поруч видно, о котрій подія закінчиться.
- Події, що перетинаються, стають поруч колонками, як у Google Календарі.
- Зверху смуга «увесь день»: заплановані завдання (кольором проєкту) і дедлайни (червоним).
- Кнопка `+` у дні відкриває список завдань, які можна поставити на цей день.

### Планер тижня
- Сім колонок Пн–Нд плюс панель **«Незаплановані»** праворуч із пошуком і фільтром за проєктом.
- **Перетягуй** картки з панелі у день, між днями, або назад у панель.
- Одне завдання можна покласти на кілька днів.
- Кнопка **→** на картці розтягує завдання на наступні дні одним кліком:
  +1 / +2 / +3 / +4 дні, до кінця тижня, лише будні до кінця тижня, тиждень, 2 тижні, місяць.
  Те саме є у панелі завдання під «Днями роботи», плюс «Прибрати всі дні».
- У шапці дня — смужка навантаження, щоб бачити, який день перевантажений.
- Кнопка `+` у дні — вибір завдань списком, якщо тягнути незручно.

### Проєкти
Створення з емодзі й кольором, перейменування, порядок, **архівування** (завдання
лишаються, проєкт ховається) і видалення. Видалення проєкту забирає його завдання.

**Будь-яке видалення питає підтвердження** — завдання, події, проєкту, «Прибрати виконані».
`Enter` — підтвердити, `Esc` — скасувати.

## Швидке додавання

| Пишеш | Значення |
| --- | --- |
| `#тег` | додає тег |
| `!високий` `!середній` `!низький` | пріоритет |
| `@сьогодні` `@завтра` `@+3` `@2026-12-01` | дедлайн |
| `*щодня` `*щотижня` `*щомісяця` `*щороку` `*будні` | повторення |
| `*3д` `*2т` `*6м` `*1р` | повторення кожні N днів/тижнів/місяців/років |

Приклад: `Полити квіти #дім !низький *щодня`

Англійські варіанти (`!high`, `@today`, `*daily`, `*3d`) теж працюють.

**Клавіші** — `n` перейти до поля додавання · `/` пошук · `Esc` закрити панель.

## На телефоні

Той самий застосунок, той самий лінк. Знизу зʼявляється панель вкладок
**Завдання · Календар · Планер · Меню**:

- **Планер** — день займає весь екран, гортається пальцем убік. Замість перетягування
  на картці кнопка «⋯»: перенести на будь-який день тижня, продовжити на кілька днів,
  прибрати. (HTML5-перетягування на iOS не працює взагалі.)
- **Календар** — «Місяць» і «День»; тижнева сітка на 7 колонок на телефоні нечитабельна,
  тому там її немає.
- Поля вводу 16px, щоб iOS не зумив сторінку; кнопки більші; врахований вирізм і
  смуга Home.

Додати на екран «Додому»: Safari → **Поділитися → На екран «Додому»**.

## Синхронізація між компʼютером і телефоном

За замовчуванням дані живуть у браузері пристрою. Щоб на телефоні й на компʼютері
було одне й те саме, потрібне місце в мережі — використовується безкоштовний
**Supabase**. Налаштовується один раз, приблизно на 5 хвилин.

### 1. Створити проєкт

1. [supabase.com](https://supabase.com) → зареєструватись → **New project**
   (регіон бери найближчий, наприклад Frankfurt).
2. Дочекатись, поки проєкт піднімуть (~2 хв).

### 2. Створити таблицю

Supabase → **SQL Editor** → **New query** → вставити й натиснути **Run**:

```sql
create table if not exists public.app_state (
  user_id uuid primary key references auth.users on delete cascade,
  data jsonb not null default '{}'::jsonb,
  updated_at timestamptz not null default now()
);

alter table public.app_state enable row level security;

create policy "own row only"
  on public.app_state
  for all
  using (auth.uid() = user_id)
  with check (auth.uid() = user_id);

-- миттєве оновлення на другому пристрої
alter publication supabase_realtime add table public.app_state;
```

Політика `own row only` — це те, що не дає одному акаунту побачити дані іншого.

### 3. Вимкнути підтвердження пошти (щоб не морочитись)

Supabase → **Authentication → Sign In / Providers → Email** → вимкнути
**Confirm email** → Save. Тоді акаунт працює одразу після реєстрації.

### 4. Вставити ключі

Найпростіше — запустити у теці проєкту:

```bash
npm run setup-sync
```

Скрипт запитає два значення, перевірить їх і сам створить файл `.env.local`.
Якщо значення вже під рукою, можна одразу:

```bash
npm run setup-sync -- https://xxxx.supabase.co eyJhbGciOi...
```

**Де ці два значення в Supabase:**

1. Відкрий проєкт на [supabase.com/dashboard](https://supabase.com/dashboard).
2. Ліворуч **унизу** — шестерня **Project Settings**.
3. Пункт **Data API** (у старіших дашбордах просто **API**) — там угорі рядок
   **Project URL**, виглядає як `https://abcdefghijkl.supabase.co`.
4. Пункт **API Keys** (у старіших — той самий екран, блок *Project API keys*) —
   бери ключ з підписом **anon · public** або **Publishable key**. Він довгий,
   починається з `eyJ` або з `sb_publishable_`.

Пряме посилання на цей екран: `https://supabase.com/dashboard/project/_/settings/api`

> Ключ **service_role** / **secret** брати не можна — він дає повний доступ до бази
> в обхід усіх правил. Скрипт такий ключ відхилить.

Ключ `anon` публічний за задумом: він лише каже, до якого проєкту стукати. Доступ
до даних дає вхід в акаунт і політика RLS з кроку 2.

### 5. Опублікувати

```bash
npm run deploy
```

### 6. Увійти на обох пристроях

У застосунку ліворуч унизу зʼявиться значок **хмарки** → «Створити акаунт»
(пошта + пароль) на компʼютері, потім **тим самим акаунтом** увійти на телефоні.
Крапка на хмарці показує стан: зелена — синхронізовано, синя — синхронізує,
жовта — немає мережі, червона — помилка.

Її акаунт — окремий, з окремими даними.

### Як воно зливає дані

Кожен запис має час зміни, кожне видалення лишає «надгробок». Правила прості:
перемагає новіша зміна, а видалення — це теж зміна. Тому правки з двох пристроїв
зберігаються обидві; якщо одне й те саме завдання змінене в обох місцях —
лишається новіша версія. Без мережі все працює локально й доганяє, щойно звʼязок
зʼявиться (синхронізація також спрацьовує при поверненні у вкладку і раз на хвилину).

## Де лежать дані

`localStorage`, ключі `tasks.app.v1` (проєкти, завдання, події) і `tasks.app.theme`.
Прив'язані до адреси `http://localhost:5173` **і** до конкретного браузера — Chrome і Safari
мають окремі копії. Обери один браузер. Кнопки експорту/імпорту JSON у нижньому лівому куті
роблять резервну копію.

## Як поставити на інший MacBook

### Спосіб 1 — просто посилання (найлегший, без Термінала)

Один раз на своєму маку:

```bash
npm run deploy
```

Скрипт збирає застосунок і публікує його на GitHub Pages. Посилання вже працює:
**https://mertagua.github.io/todo/**. Далі їй треба лише:

1. відкрити посилання у Safari;
2. меню **Файл → Додати в Dock** (macOS Sonoma і новіші). У Chrome те саме — значок
   «Встановити» у правій частині адресного рядка.

Виходить окреме вікно з іконкою в Dock, без вкладок і адресного рядка. Застосунок
кешується service worker-ом, тож після першого відкриття працює **і без інтернету**.
Її завдання зберігаються у неї в браузері, до сервера нічого не йде.

Що варто знати: репозиторій публічний, бо цього вимагають безкоштовні GitHub Pages —
публічним є **код**, не дані. Оновлення застосунку — знову `npm run deploy`,
у неї підтягнеться саме́ (service worker бере нову версію при наступному відкритті
з інтернетом).

### Спосіб 2 — локально, як у тебе

Якщо публікувати не хочеться, тоді все ставиться руками. Синхронізації між
компʼютерами немає — кожен має свої дані.

1. **Node.js.** Перевір у Терміналі: `node -v`. Якщо команда не знайдена — постав LTS
   з [nodejs.org](https://nodejs.org) (звичайний інсталятор `.pkg`) або `brew install node`.
2. **Скопіюй теку проєкту** — AirDrop, флешка або `git clone`. Теку `node_modules`
   копіювати не треба.
3. У Терміналі:
   ```bash
   cd ~/Documents/todo      # шлях, куди скопіювала теку
   npm install
   npm run app
   ```
4. Spotlight (`⌘Space`) → «Завдання» → застосунок відкриється. Перетягни іконку в Dock.

Щоб перенести наявні завдання: на своєму маку натисни іконку експорту (стрілка вниз
у лівому нижньому куті), надішли `.json`, на її маку — іконку імпорту (стрілка вгору).

## Якщо ти новачок у Vue 3 — читай у такому порядку

1. `src/store/store.js` — `reactive()` робить обʼєкт відстежуваним, `computed()` рахує
   похідні значення, `watch(..., { deep: true })` пише у localStorage. Ні Pinia, ні Vuex:
   компоненти просто роблять `import { state }`.
2. `src/components/TaskRow.vue` — маленький компонент: `defineProps`, `computed`,
   `v-if` / `v-for`, `@click.stop`, `:class`, `<style scoped>`.
3. `src/components/PlannerView.vue` — стан перетягування, обчислення тижня, drag-and-drop
   без бібліотек.
4. `src/App.vue` — складання розділів докупи, `onMounted` / `onBeforeUnmount`.

Правило по всьому проєкту: **логіка живе у сторі, компоненти лише малюють і викликають actions.**
